# 섹터 분석 데이터·지표 계약서 (Data & Metric Contract)

- 문서 상태: 설계 확정안 (SPEC 작성 입력용)
- 기준 측정일: 2026-08-11 (weekly DB 최신 bar), 2026-08-12 작성
- 측정 대상: `Output/stock_data_weekly.db`, `Output/stock_data_daily.db`, `Input/sectormap-original.xlsx`
- 이 문서의 모든 수치는 위 DB에 대해 실제로 실행한 read-only 쿼리 결과다. 추정치는 없다.

---

## 1. 목적과 범위

### 1.1 이 계약서가 규정하는 것

섹터 분석 화면(Table / Bubble / RRG / Bump)과 Stock Explorer가 **같은 숫자를 같은 의미로** 보여주기 위한 데이터·지표 규약이다. 구체적으로 다음을 확정한다.

1. 사용자에게 보이는 모든 지표의 **정의·계산식·입력 출처·결측 처리·표시 규칙**
2. "1주 / 1개월 / 3개월", "40주선", "52주 신고가" 같은 **기간 표현의 정확한 의미**
3. 섹터 구성종목의 **단일 소속 기준(유니버스)**
4. 종목 → 섹터 **집계 방식(가중·상한·최소 구성수·커버리지)**
5. 초과수익률의 **벤치마크 선정과 정합성 조건**
6. 모든 API 응답이 공유해야 할 **기준일(스냅샷) 규약**
7. 화면별 **필수 필드와 값 부재 시 표시 규칙**

### 1.2 이 계약서가 규정하지 않는 것

- **화면 구조·IA**: 현행 4탭(Table / Bubble / RRG / Bump)과 Stock Explorer 레이아웃을 그대로 유지한다. 신규 화면·신규 IA는 이 문서의 범위 밖이다.
- **구현 방법**: 어떤 함수를 고칠지, 어떤 계층에 캐시를 둘지는 규정하지 않는다. 코드 매핑은 부록 A에만 둔다.
- **관심 섹터 모니터링(워치리스트)**: 별도 SPEC으로 이관.
- **데이터 수집 파이프라인의 재설계**: 단, §3에서 수집 결과가 만족해야 할 불변식(invariant)은 규정한다. 그 불변식을 어떻게 만족시킬지는 구현 판단이다.

### 1.3 대상 사용자 워크플로

| ID | 워크플로 | 이 계약서가 지지하는 방식 |
|----|---------|--------------------------|
| W1 | 섹터에서 종목 발굴 (top-down) | 섹터 순위 → 섹터 상세 → 종목 서열이 **동일 기준일·동일 유니버스·동일 필터**로 연결됨 |
| W2 | 섹터 로테이션 추적 | RRG·Bump가 **달력 기준 고정 주간 격자** 위에서 계산되어 시점 비교가 성립함 |
| W3 | 섹터 내 종목 서열 비교 | 섹터 집계에 쓰인 가중치와 종목 목록의 정렬 기준이 **명시적으로 노출**됨 |

## 2. 용어·지표 사전

### 2.0 공통 규약

- **수익률 단위**: DB의 `CHG_*` 컬럼은 **소수(0.02 = 2%)**로 저장되어 있다. 사용자 표시는 항상 **퍼센트(%)** 이며, 변환은 집계 계층에서 1회만 수행한다.
- **반올림 시점**: 반올림은 **응답 직전 1회**만 수행한다. 중간 계산·정렬·순위 비교에는 절대 반올림된 값을 쓰지 않는다. (현행 결함: 당월 composite는 2dp 반올림, 전월 composite는 반올림 없음 → 동점 순서가 어긋나 허수 ±1 순위변동이 발생한다.)
- **결측의 의미 분리**: 모든 지표는 `값 없음(null)` / `실제 0` / `계산 불가` 세 상태를 구분한다. §9 참조.
- **분모 규칙**: 결측 종목은 **분자에서 빼면 분모에서도 빼야 한다.** 결측을 0으로 치환한 뒤 분모에 남기는 처리는 금지한다.

### 2.1 섹터 수익률 (sector_return)

| 항목 | 내용 |
|------|------|
| 정의 | 해당 섹터 구성종목의 **시가총액 가중(종목별 상한 적용)** 기간 수익률 |
| 계산식 | `Σ(wᵢ × rᵢ) / Σwᵢ`, `wᵢ` = §5.2의 상한 적용 가중치, `rᵢ` = 종목 i의 기간 수익률(%) |
| 입력 필드 | `stock_prices.CHG_1W / CHG_1M / CHG_3M` (weekly DB), `stock_meta.market_cap` (daily DB) |
| 결측 처리 | `CHG_*`가 NULL인 종목은 **해당 기간 계산에서 완전 제외**(분자·분모·가중치 정규화 모두에서). 0으로 치환하지 않는다. |
| 표시 | `%`, 소수 2자리, 부호 표기(+/−) |
| 답하는 질문 | "이 섹터는 최근 N기간 동안 얼마나 올랐나?" |

**필수 동반 필드**: `coverage_ratio`(§5.5), `member_count`, `capped_member_count`(상한에 걸린 종목 수).

**사용자에게 보이는 변화**: 등가중 → 시총가중 전환으로 순위가 크게 바뀐다. 1M 기준 실측(cap 10%):

| 섹터 | 등가중 1M | 시총가중 1M | 등가중 순위 → 시총가중 순위 |
|------|----------|------------|--------------------------|
| 헬스케어 | +9.23% | +17.07% | 8위 → 3위 |
| 비철금속 | +9.32% | +16.61% | 7위 → 4위 |
| 건설 | +4.90% | +11.49% | 18위 → 8위 |
| 지주사 | +5.52% | +2.06% | 15위 → 25위 |
| 반도체 | +2.49% | −6.59% | 26위 → 29위 |
| 금융 | +3.92% | −4.42% | 23위 → 28위 |

평균 순위 이동은 3.5계단, 최대 10계단이다. **이는 버그가 아니라 정의 변경이다.** 반도체가 최하위로 내려가는 것은 삼성전자·SK하이닉스(섹터 시총의 95.4%를 상위 3종목이 차지)의 하락이 반영된 결과이며, 시총가중의 의도된 동작이다.

### 2.2 초과수익률 (excess_return)

| 항목 | 내용 |
|------|------|
| 정의 | 섹터 수익률 − **동일 방법론으로 산출한 시장 벤치마크 수익률** |
| 계산식 | `excess = sector_return(period, market) − benchmark_return(period, market)` |
| 입력 필드 | §2.1과 동일 + §6의 벤치마크 |
| 결측 처리 | 벤치마크 산출 불가 시 **초과수익률은 null**이며, 원수익률을 대신 표시하지 않는다(§6.3) |
| 표시 | `%p`, 소수 2자리, 부호 표기. 0 기준선 기준 좌우 배치 |
| 답하는 질문 | "이 섹터는 시장보다 잘했나?" |

**불변식 EX-1**: 섹터 수익률과 벤치마크 수익률은 **같은 가중 방법론·같은 상한·같은 날짜 창**으로 계산되어야 한다.

**불변식 EX-2**: 전체 섹터의 초과수익률이 **모두 같은 부호이면 안 된다**(단일 시장·단일 기간 기준). 모두 양수/음수이면 벤치마크 정합성 결함으로 간주하고 경고를 기록한다.

**사용자에게 보이는 변화 — 중요**: 현재는 29개 섹터의 1W 초과수익률이 **전부 양수**(+0.056% … +8.175%)라서 X=0 기준선이 아무 정보도 주지 않는다. 원인은 두 가지이며, 두 번째가 지배적이다.

1. 등가중 섹터 평균을 시총가중 지수와 비교 (1W 기준 +2.59%p 상시 편향)
2. **KOSDAQ 종목을 포함한 섹터 집계를 KOSPI 단일 지수와 비교**. 실측 1M: KOSPI −6.97%, KOSDAQ +8.34% (15.3%p 격차). 종목 수 기준 KOSDAQ이 1,719 / 2,546(67.5%)이므로, All 유니버스 섹터를 KOSPI에 대볼 때 구조적 양(+) 편향이 생긴다.

§5·§6 규약 적용 후 실측 결과 — **초과수익률이 양방향으로 벌어진다**:

| 기간 | 벤치마크(상한적용 시총가중, All) | 양수 섹터 수 | 최저 | 최고 |
|------|------------------------------|------------|------|------|
| 1W | +1.88% | **18 / 29** | −2.60%p (운송) | +8.59%p (반도체) |
| 1M | −0.25% | 25 / 29 | −6.34%p (반도체) | +19.22%p (화장품) |
| 3M | −15.74% | **15 / 29** | −18.30%p (배터리) | +27.33%p (화장품) |

1M이 여전히 25/29 양수인 것은 결함이 아니라 **실제 시장 상태**다. 해당 구간에 초대형주(삼성전자 전체 시총의 25.61%, SK하이닉스 18.34%)가 하락하고 중소형주가 상승했으므로, 대부분의 섹터가 시총가중 시장을 이기는 것이 정상이다. 이제 이 값은 "시장 폭(breadth)이 넓다"는 해석 가능한 신호다.

### 2.3 RS 평균 (rs_avg)

| 항목 | 내용 |
|------|------|
| 정의 | 섹터 구성종목의 `RS_12M_Rating` **단순 평균** (등가중) |
| 계산식 | `Σ RSᵢ / n_valid`, `n_valid` = RS 값이 존재하는 종목 수 |
| 입력 필드 | `relative_strength.RS_12M_Rating` (weekly DB, `(Name, Date)` 조인) |
| 결측 처리 | RS 행이 없는 종목은 **분자·분모 모두에서 제외**. 0 치환 금지 |
| 표시 | 0–100 스케일, 소수 1자리 |
| 답하는 질문 | "이 섹터 종목들의 시장 대비 상대강도 수준은?" |

**등가중을 쓰는 이유**: RS는 이미 0–100 백분위 점수라 시총가중이 의미를 왜곡한다. 시총가중 RS는 "대형주 1종목의 RS"에 수렴한다. 수익률(§2.1)과 가중 방식이 다른 점을 UI에 명시해야 한다.

**필수 동반 필드**: `rs_coverage` = `n_valid / member_count`.

**사용자에게 보이는 변화**: 최신일 기준 **58개 종목**에 `RS_12M_Rating` 행이 없다. 현행은 이를 0으로 치환하고 분모에 남겨 평균을 끌어내린다. 제외 처리 시 실측 상승폭 — 방산 45.64 → 51.34, 조선 38.87 → 43.19, 헬스케어 45.21 → 47.92. **RS 평균이 전반적으로 올라가는 것이 정상이다.**

### 2.4 RS 상위 비율 (rs_top_pct)

| 항목 | 내용 |
|------|------|
| 정의 | 구성종목 중 `RS_12M_Rating >= 80`인 종목의 비율 |
| 계산식 | `count(RS >= 80) / n_valid × 100` |
| 입력 필드 | `relative_strength.RS_12M_Rating` |
| 결측 처리 | RS 없는 종목은 분모에서 제외. 임계값 80은 고정 상수이며 UI에 명시 |
| 표시 | `%`, 소수 1자리 |
| 답하는 질문 | "이 섹터에 강한 종목이 몇 %나 있나?" (§2.3의 평균이 가리지 못하는 분포 정보) |

### 2.5 52주 신고가 비율 (nh_pct)

| 항목 | 내용 |
|------|------|
| 정의 | 종가가 **직전 52 달력주 최고가(High)의 98% 이상**인 종목의 비율 |
| 계산식 | `count(Close >= high_52w × 0.98) / n_valid × 100` |
| 입력 필드 | `Close`(weekly), 52주 최고가 = **`MAX(High)` over 직전 364일** (또는 daily `stock_meta.high52w`) |
| 결측 처리 | 52주 최고가 산출 불가(상장 1년 미만 등) 종목은 분모에서 제외 |
| 표시 | `%`, 소수 1자리. 근접 밴드 2%를 라벨에 명시("52주 고점 2% 이내") |
| 답하는 질문 | "이 섹터에서 신고가를 뚫는 종목이 몇 %인가?" |

**현행 `MAX52` 컬럼을 쓰지 않는 이유** — 실측 두 가지 오류:

1. **Close 기반**: `price.py`의 `MAX 52W = Close.rolling(52).max()`. 고가가 아니라 종가의 최대값이다. 실측 KOSPI: 저장된 `MAX52` = 9052.42, 실제 52주 최고 `High` = 9385.59 (**−3.5%**).
2. **전 종목 체계적 과소**: 최신일 2,500종목 표본에서 `저장 MAX52 / 실제 52주 High` 중앙값 **0.9155**, 평균 0.8931. **91.7%의 종목**에서 저장값이 실제 고점의 98% 미만이다.

결과적으로 `Close >= MAX52 × 0.98` 판정은 기준선이 낮아 **신고가 종목을 과대 계상**한다.

**사용자에게 보이는 변화 — 중요**: 최신일 실측으로 신고가 종목이 **99개(4.0%) → 56개(2.2%)** 로 줄어든다. **신고가 비율이 거의 절반으로 떨어지는 것이 올바른 동작이다.** 릴리스 노트에 반드시 명시해야 한다.

**추가 결함**: 최신일 2,548행 중 **48행**의 `MAX52`가 NULL인데 현행은 분모에 남아 있다. 제외 처리 대상이다.

### 2.6 Stage 2 비율 (stage2_pct)

| 항목 | 내용 |
|------|------|
| 정의 | Weinstein Stage 2(상승국면)로 분류된 종목의 비율 |
| 계산식 | `count(stage == 2) / n_valid × 100` |
| 분류기 | **`my_chart/analysis/stage_classifier.py`의 `classify_stage`(주봉 기준) 단일 사용** |
| 입력 필드 | `Close`, `SMA10`, `SMA40`, `SMA40_Trend_4M`, `RS_12M_Rating`, `Volume`, `VolumeSMA10` |
| 결측 처리 | `SMA40` 또는 `SMA10`이 NULL인 종목은 **분류 불가**로 분모에서 제외 (0 치환 금지) |
| 표시 | `%`, 소수 1자리. Stage 1/2/3/4 분포를 함께 노출 |
| 답하는 질문 | "이 섹터가 상승국면에 있는 종목 비중은?" |

**단일화 결정**: `backend/services/sector_detail_service.py`의 일봉 근사 분류는 **폐기**한다. 같은 종목이 화면에 따라 다른 Stage로 표시되는 문제를 제거하기 위함이다.

**신뢰도 참고**: `SMA10` / `SMA40` / `SMA40_Trend_4M`은 수집 시점의 **원천 주봉 시계열**에서 계산되어 저장되므로, §3의 DB 격자 오염에 상대적으로 덜 노출된다. 실측 검증: 최신일 200종목 표본에서 저장 `SMA40`이 "DB 최근 40행 평균"과 0.5% 이내 일치하는 경우는 15/200에 불과했고, "40 달력주 DB행 평균"과는 37/200 일치했다. 즉 저장값은 **DB 행이 아니라 원천 시계열 기준**이며, 이는 Stage 분류가 §3의 재앵커링 대상 중 **우선순위가 낮은** 항목임을 뜻한다.

### 2.7 거래대금 (trading_value)

| 항목 | 내용 |
|------|------|
| 정의 | 섹터 구성종목의 기간 거래대금 합계 (원) |
| 계산식 | `Σ VolumeWon` over **기간 토글과 동일한 창** — `[anchor(t, N), t]`, N = 1W→7일 / 1M→28일 / 3M→91일 (§3.4, §10 O-10 결정) |
| 입력 필드 | **`stock_prices.VolumeWon` (daily DB)** |
| 결측 처리 | NULL 종목 제외 + `coverage_ratio` 동반 표기 |
| 표시 | 조/억 단위 축약, 정수 |
| 답하는 질문 | "이 섹터에 돈이 얼마나 들어와 있나?" |

**`Close × Volume`을 쓰지 않는다.** daily DB에 `VolumeWon` 컬럼이 존재하며 최신일 2,546행 중 **NULL 0건**으로 완전하다. 원시 데이터에서 재계산하지 않는다.

### 2.8 거래량 비율 (volume_ratio)

| 항목 | 내용 |
|------|------|
| 정의 | 당기 거래량 ÷ 10주 평균 거래량 |
| 계산식 | `Volume / VolumeSMA10` |
| 입력 필드 | `stock_prices.Volume`, **`stock_prices.VolumeSMA10`** (weekly DB) |
| 결측 처리 | `VolumeSMA10`이 NULL이거나 0이면 **null**(계산 불가). 1.0으로 치환 금지 |
| 표시 | 배수(x), 소수 1자리 |
| 답하는 질문 | "평소보다 거래가 얼마나 터졌나?" |

**현행 결함**: `sector_advanced.py`가 `volume_sma10 = sma10`으로 **가격 이동평균을 거래량 기준선으로** 사용한다. 그 결과 `volume_ratio`는 "거래량 ÷ 주가"라는 무의미한 값이다. weekly DB에 실제 `VolumeSMA10` 컬럼이 존재하므로 이를 사용한다.

### 2.9 순위 (rank)

| 항목 | 내용 |
|------|------|
| 정의 | composite_score 내림차순 서열 (1 = 최상위) |
| 계산식 | §5.6의 composite_score로 정렬 |
| 결측 처리 | §5.4의 최소 구성수·커버리지 미달 섹터는 **순위 부여 대상에서 제외**하고 별도 표기 |
| 표시 | 정수. 총 섹터 수 동반 표기("7 / 29") |
| 답하는 질문 | "이 섹터는 전체에서 몇 번째인가?" |

**불변식 RK-1 (결정적 타이브레이크)**: 정렬 키는 `(−composite_score_unrounded, sector_name)`이다. composite가 동일하면 섹터명 사전순으로 확정한다. 레지스트리 삽입 순서에 의존하는 현행 동작은 금지한다.

**불변식 RK-2**: 반올림된 값으로 정렬하지 않는다. 표시용 반올림은 정렬 이후에만 적용한다.

### 2.10 순위변동 (rank_change)

| 항목 | 내용 |
|------|------|
| 정의 | **직전 4 달력주 기준일**의 순위 − 현재 순위 (양수 = 상승) |
| 계산식 | `rank_change = rank(t−4주) − rank(t)`, 기준일은 §3.3의 정규 격자에서 선택 |
| 결측 처리 | 비교 기준일이 없거나 해당 섹터가 당시 순위 대상이 아니었으면 **null**(0이 아님) |
| 표시 | `▲n` / `▼n` / `−`. null은 `신규` 또는 `–` |
| 답하는 질문 | "이 섹터의 상대적 위치가 최근 한 달 사이 좋아졌나?" |

**필수 동반 필드**: `baseline_date` — 비교에 실제로 사용된 날짜를 응답에 포함해 UI가 "4주 전(2026-07-14) 대비"처럼 검증 가능하게 표기한다.

**현행 결함**: `LIMIT 1 OFFSET 3`으로 "4주 전"을 의도하지만 DB 행 기준이라 실제로는 2026-07-31, 즉 **11 달력일** 전이 선택된다. §3의 정규 격자 위에서 달력 기준으로 재선정해야 한다.

### 2.11 RRG RS-Ratio

| 항목 | 내용 |
|------|------|
| 정의 | 벤치마크 대비 섹터의 **상대강도 수준**. 100 = 벤치마크와 동일 |
| 계산식 | `RS_Ratio(t) = RS_line(t) = sector_index(t) / benchmark_index(t) × 100`. **롤링 정규화를 적용하지 않는다** (결정 2026-08-12) — 그래야 100이 문자 그대로 벤치마크다 |
| 입력 필드 | §5의 섹터 지수, §6의 벤치마크 지수 |
| 결측 처리 | 워밍업 미달 구간은 **미발행**(null). 상수로 채우지 않는다 |
| 표시 | 소수 2자리. 사분면 경계선 100 |
| 답하는 질문 | "이 섹터는 시장보다 강한가, 약한가?" |

**불변식 RRG-1 (핵심)**: RS-Ratio의 100은 **벤치마크 대비 동일 성과**를 의미해야 한다. 현행은 `100 + z×10`에서 z가 **횡단면(cross-sectional) z-score**이므로 100은 "그날 29개 섹터의 평균"이다. 프론트엔드(`RRGChart.tsx`)는 100을 벤치마크 기준선으로 그리므로, **시장 방향과 무관하게 항상 절반가량의 섹터가 Lagging/Weakening으로 표시된다.** 강세장에서도 절반은 약세로 보이는 구조적 오류다. 같은 파일에 `_get_benchmark_return`이 이미 존재하나 RRG 경로에서 사용되지 않는다.

**RRG-1 보강 — 롤링 정규화 미적용 (결정 2026-08-12, 이전 판의 내부 모순 해소)**

이 문서의 이전 판은 계산식 칸에서 "자기 시계열 기준 롤링 정규화"를 요구하면서 동시에 "중심 100은 벤치마크 자신"을 요구했다. **두 요구는 양립할 수 없다** — 자기 시계열 롤링 정규화(z-score 등)를 적용하면 중심 100은 "그 섹터 자신의 과거 평균"이 되어 다시 벤치마크가 아니게 된다. 표준 JdK RRG가 바로 그 방식이다.

**확정**: 롤링 정규화를 **적용하지 않고** `RS_line`을 그대로 RS-Ratio로 발행한다. 100은 문자 그대로 "벤치마크와 동일 성과"다.

- **표준 JdK RRG와의 차이를 명시한다.** 이 프로젝트의 RS-Ratio는 정규화되지 않은 상대강도 비율이며, 상용 RRG 도구(StockCharts 등)의 값과 직접 비교할 수 없다. 화면 범례에 이를 표기할 의무는 `02-screen-flow.md §9.4 VZ-7`이 진다.
- **강세장에서 다수 섹터가 Leading 사분면에 몰리는 것은 올바른 동작이다.** 100이 진짜 벤치마크이므로, 시장 폭이 넓은 국면에서는 대부분의 섹터가 벤치마크를 상회한다. 사분면 균등 분포를 요구하는 테스트를 두어서는 안 된다 (`02-screen-flow.md §12.2` 사분면 편중 항목).
- **섹터별 스케일 차이의 대가를 감수한다.** 정규화가 없으므로 섹터 간 RS-Ratio 분산 폭이 다를 수 있다. 축 범위 자동 대칭(`02 §9.4 VZ-8`)이 이를 흡수한다.
- RS-Momentum(§2.12)도 동일하게 정규화 없이 `RS_Ratio` 시계열의 변화율로 산출하며, `lookback_weeks` 창은 워밍업 미발행(RRG-2) 판정에만 쓴다.

**불변식 RRG-2 (워밍업 미발행)**: 롤링 정규화의 워밍업 구간(lookback−1개)을 상수 100.0으로 채우고, 그 구간을 차분해 모멘텀을 만드는 처리를 금지한다. 상수 구간의 차분은 0이므로 최초 약 12개 모멘텀 점이 인위적으로 0에 눌린다. **워밍업 구간은 아예 발행하지 않는다.**

**불변식 RRG-3 (지수 연쇄)**: 섹터 지수는 **수익률의 연쇄(chained)** 로 구성한다. 각 날짜마다 `Σ(close×cap)/Σcap`을 독립 재계산하는 방식은 구성종목 변동이 지수 레벨의 점프로 나타난다. 실측 전자제품: 862,009 → 891,139 → 771,586 → 912,684 (구성종목 수가 동일한 구간에서 ±14% 계단).

**불변식 RRG-4 (look-ahead 금지)**: 과거 날짜의 지수에 **현재 시점 `stock_meta` 스냅샷의 시가총액**을 적용하는 것을 금지한다. 현행은 미래 정보를 과거에 주입하는 look-ahead bias다. 시점별 시총 이력이 없다면 **각 날짜의 시총을 `Close × 상장주식수`로 역산**하거나, 그것이 불가능하면 **가중치 고정 시점을 명시**하고 UI에 한계를 표기한다(§10 미결 O-3).

### 2.12 RRG RS-Momentum

| 항목 | 내용 |
|------|------|
| 정의 | RS-Ratio의 변화 속도. 100 = 상대강도 변화 없음 |
| 계산식 | RS-Ratio 시계열의 변화율. **정규화하지 않는다**(RRG-1 확정과 동일). `lookback_weeks` 창은 워밍업 미발행(RRG-2) 판정에만 쓴다 |
| 결측 처리 | RS-Ratio가 미발행인 구간 + 차분 1점 추가 미발행 |
| 표시 | 소수 2자리 |
| 답하는 질문 | "이 섹터의 상대강도가 개선되는 중인가, 꺾이는 중인가?" |

RRG-2 / RRG-3 / RRG-4가 동일하게 적용된다.

## 3. 시간 축 규약

**이 절이 이 계약서에서 가장 중요하다.** 현재 모든 "N주" 표현이 실제 기간과 일치하지 않는다.

### 3.1 문제의 정확한 성격

`my_chart/db/weekly.py`는 `PRIMARY KEY (Name, Date)` 위에 `INSERT OR REPLACE`를 사용한다. 주중에 갱신을 돌리면 **미완성 주간 바가 그날 날짜로 기록되고, 주가 끝나도 삭제되지 않는다.** 결과적으로 한 ISO 주에 여러 행이 남는다.

실측 (전체 이력 346 ISO주):

| 항목 | 값 |
|------|-----|
| 전체 ISO 주 수 | 346 |
| 행 날짜가 2개 이상인 주 | **21** |
| 금요일 바가 없는 주 | 21 |
| 전체 바 날짜 요일 분포 | 금 325 / 목 21 / 수 16 / 화 13 / 월 10 |

오염은 **최근 6개월에 집중**되어 있다. 최근 24주 실측 예:

```
2026-W33: 08-11(화, 2546행) | 08-10(월, 2547행)     ← 진행 중인 주
2026-W32: 08-07(금, 2548행) | 08-05(수, 2548행)     ← 중복
2026-W30: 07-24(금, 2548행) | 07-23(목,    1행)     ← 부분 데이터
2026-W28: 07-10(금, 2551행) | 07-07(화, 1행) | 07-06(월, 2553행)
2026-W23: 06-05(금) | 06-04(목) | 06-02(화) | 06-01(월)   ← 한 주에 4개 바
```

### 3.2 실측된 영향 — "N주"는 N주가 아니다

DB 행을 세어 기간을 만드는 모든 계산이 어긋난다.

| 조회 | 실제 달력 범위 | 실제 주 수 | 의도 대비 |
|------|--------------|-----------|----------|
| 최근 **12행** (RRG lookback, `compute_sector_history(weeks=12)`) | 2026-07-06 → 08-11, **36일** | 5.1주 | **43%** |
| 최근 **40행** (40주선 상당 구간) | 2026-04-30 → 08-11, **103일** | 14.7주 | **37%** |
| 최근 **52행** (52주 구간) | 2026-03-25 → 08-11, **139일** | 19.9주 | **38%** |
| `LIMIT 1 OFFSET 3` (rank_change "4주 전") | 2026-07-31 | 11일 | **39%** |

즉 최근 구간에서 "N주"는 실제로 **약 0.38N주**다.

**적용 범위의 중요한 한정**: 이 왜곡은 **DB 행을 세어 창(window)을 만드는 계산**에만 적용된다. `SMA10` / `SMA40` / `MAX52` / `CHG_*`는 **수집 시점의 원천 주봉 시계열**에서 계산되어 컬럼으로 저장되므로 이 왜곡을 거의 받지 않는다(§2.6 실측 검증). 따라서 재앵커링 우선순위는 다음과 같다.

- **1순위 (직접 왜곡)**: `compute_sector_history`, RRG lookback, rank_change 기준일 선택, 모든 히스토리 조회
- **2순위 (간접·경미)**: Stage 분류(저장 컬럼 사용), `CHG_*` 기반 수익률
- **별개 문제**: `MAX52`는 시간축이 아니라 **Close vs High** 정의 오류다(§2.5)

### 3.3 정규 주간 격자 (Canonical Weekly Grid)

**규칙 CG-1**: 각 ISO 주(연도, 주차)에 대해 **해당 주의 최대 날짜 1개만**을 정규 바로 채택한다.

실측 검증 — 다중 날짜 주 전부에서 최대 날짜가 그 주의 정상 바와 일치한다:
- W32: max(08-07금, 08-05수) = **08-07(금)** ✓
- W28: max(07-10금, 07-07화, 07-06월) = **07-10(금)** ✓
- W27: max(07-03금, 06-30화, 06-29월) = **07-03(금)** ✓

금요일이 없는 주(공휴일 등 21주)에서도 최대 날짜가 그 주의 마지막 거래일이므로 규칙이 성립한다.

**규칙 CG-2 (진행 중인 주)**: 최신 ISO 주에 금요일 바가 없고 그 주가 아직 끝나지 않았다면 **미완성 바**로 표시한다. 이 바는 최신 스냅샷으로는 사용하되, **히스토리·롤링 계산·기준일 비교에서는 제외**한다. 2026-08-11(화, W33)이 이 경우다.

**규칙 CG-3 (부분 데이터 배제)**: 정규 바로 선택된 날짜의 행 수가 조회 구간 중앙값의 50% 미만이면 배제한다. (기존 `sector_metrics.py`의 중앙값 가드를 전 엔드포인트로 확대 적용. 현행은 `compute_sector_history`에만 존재하고 `sector_ranking_service` / `stage_service` / `sector_advanced` / `market_service` / `meta_service`에는 없다.) 실측 부분 데이터 날짜: 2026-07-23(1행), 07-14(1행), 07-07(1행), 06-11(1행), 06-30(4행).

**규칙 CG-4**: CG-1~CG-3은 **모든 엔드포인트가 공유하는 단일 함수**로 구현되어야 한다. 화면마다 다른 격자를 쓰면 W2(로테이션 추적)가 성립하지 않는다.

### 3.4 기간 정의 — 달력 앵커링

**규칙 CP-1**: 모든 기간은 **달력 기준**으로 정의하고, 정규 격자에서 해당 날짜 이하의 가장 가까운 바를 선택한다.

| 표기 | 정의 | 앵커 |
|------|------|------|
| 1W | 기준일 − 7일 | `t − 7d` 이하 최근 정규 바 |
| 1M | 기준일 − 28일 (4주) | `t − 28d` 이하 최근 정규 바 |
| 3M | 기준일 − 91일 (13주) | `t − 91d` 이하 최근 정규 바 |
| 6M | 기준일 − 182일 (26주) | `t − 182d` 이하 최근 정규 바 |
| 12M / 52W | 기준일 − 364일 (52주) | `t − 364d` 이하 최근 정규 바 |

**규칙 CP-2**: "N주"라는 파라미터명은 **주 수(week count)** 를 의미하며 행 수(row count)를 의미하지 않는다. 아래 파라미터는 모두 달력 기준으로 재앵커링한다.

| 파라미터 | 현재 의미 | 계약상 의미 |
|---------|----------|------------|
| `compute_sector_history(weeks=12)` | 최근 12행 (실측 36일) | 최근 12 정규 주간 바 (84일) |
| RRG lookback = 12 | 최근 12행 (실측 5.1주) | 최근 12 정규 주간 바 |
| rank_change baseline | `OFFSET 3` (실측 11일) | `t − 28d` 이하 최근 정규 바 |
| 52주 최고가 | `Close.rolling(52)` | `MAX(High)` over `t − 364d` (§2.5) |
| 40주선 (SMA40) | 원천 시계열 40행 | 유지 (§2.6, 재앵커링 불필요) |

### 3.5 검증 가능한 불변식

**불변식 TG-1 (핵심·이 계약서를 반증 가능하게 만드는 조건)**
> 정규 격자에서 최근 364일을 조회하면 바가 **52 ± 1개** 나와야 한다.

현재 실측: 최근 52행이 139일(≈20주)을 덮으므로 **이 불변식은 지금 실패한다.** 이 조건이 회귀 테스트가 된다.

**불변식 TG-2**
> 정규 격자의 어떤 ISO 주에도 바가 2개 이상 존재하지 않는다.

**불변식 TG-3**

**이전 판의 모순 해소 (2026-08-12)**: 이전 문장은 "모든 간격이 6–10일이다"와 "예외는 격자에서 제외하지 않는다"를 동시에 요구해, 예외를 유지하면 불변식이 깨지고 불변식을 지키면 예외를 제외해야 하는 자기모순이었다. 판정 대상을 "기록되지 않은 쌍"으로 한정해 두 요구를 양립시킨다. 범위를 벗어난 쌍은 **격자에서 제외하지 않고 유지**하며, `{from, to, gap_days}`로 반드시 기록된다.

### 5.2 결정: 종목별 가중치 상한 = **10%**

**근거**:
1. **상한 없음은 사용 불가**. 비철금속의 유효 종목수 1.8은 "섹터 지표"가 아니라 "고려아연 주가"다. 사용자가 섹터를 보는 이유(W3: 섹터 내 서열 비교)가 성립하지 않는다.
2. **10%는 모든 섹터에 최소 12.7개의 유효 종목을 보장**한다. 상한 20%에서는 방산의 유효 종목수가 5.3까지 떨어져 여전히 소수 종목이 지배한다.
3. **10%는 모든 29개 섹터에 실제로 구속력을 갖는다** — 상한이 규칙으로서 일관되게 작동한다. 15% 이상에서는 일부 섹터만 걸려 섹터 간 방법론이 달라진다.
4. **실행 가능성**: 최소 섹터인 방산의 구성종목이 18개이므로 10% 상한(최소 필요 10종목)이 성립한다.
5. **대형주 정보를 버리지 않는다**. 삼성전자는 반도체 섹터에서 55.1% → 10%로 낮아지지만 여전히 최대 가중이며, 실측상 반도체의 시총가중 1M(−6.59%)은 등가중(+2.49%)과 명확히 구분되는 정보를 유지한다.

**규칙 AG-1 (가중치 산출 — 반복 상한·재배분)**
```
1. wᵢ = capᵢ / Σcap          (필터 적용 후 유효 유니버스 내)
2. cap_eff = max(0.10, 1/N)   (N < 10일 때 상한 자동 완화 — 실행 가능성 보장)
3. 반복:
     over = {i : wᵢ > cap_eff}
     over가 비면 종료
     excess = Σ(wᵢ − cap_eff) for i in over
     over의 wᵢ := cap_eff
     나머지에 excess를 현재 비중에 비례 배분
4. Σwᵢ = 1 확인
```
수렴은 실측상 모든 섹터에서 5회 이내다.

**규칙 AG-2 (상한 적용 사실의 노출)**: 응답에 `weight_cap = 0.10`과 `capped_members`(상한에 걸린 종목명·원비중)를 포함한다. 사용자가 "삼성전자가 55%가 아니라 10%로 들어갔다"를 확인할 수 있어야 한다.

### 5.3 market_cap 결측 시 대체

**규칙 AG-3**: `market_cap`이 NULL/≤0인 종목은 **시총가중 집계에서 제외**한다. 대체값(1.0, 중앙값 등) 부여를 금지한다 — 등가중 대체는 소형주에 과대 가중을 주고, 중앙값 대체는 존재하지 않는 정보를 만든다.

**규칙 AG-4 (전량 결측 시)**: 섹터 내 유효 시총 종목이 §5.4 최소치 미만이면 해당 섹터의 시총가중 지표는 **null**이며, 등가중 지표만 제공하고 UI에 방법론 차이를 표기한다.

### 5.4 최소 구성종목 수

**규칙 AG-5**: 필터 적용 후 유효 종목이 **5개 미만**인 섹터는 순위·버블·RRG 대상에서 제외하고 "표본 부족(n=k)"으로 표기한다. 목록에서 숨기지 않는다 — 사용자가 섹터의 존재 자체를 놓치면 W1이 깨진다.

**임계값 5의 근거**: All 유니버스에서 최소 섹터는 방산(18)이라 어떤 임계값도 구속하지 않는다. 구속력은 시장 필터 시 발생한다 — KOSPI 필터에서 디스플레이(4), 스마트폰(4)이 5 미만으로 제외되고, PCB(5)·게임(6)은 경계에서 유지된다. 5는 §5.2 상한 규칙의 자동 완화(cap_eff = 1/5 = 20%)가 여전히 의미 있는 하한이다.

### 5.5 커버리지 비율

**규칙 AG-6**: 모든 섹터 집계 응답은 다음을 동반한다.

| 필드 | 정의 |
|------|------|
| `member_count` | 필터 적용 후 섹터 소속 종목 수 |
| `valid_count` | 해당 지표를 실제로 계산할 수 있었던 종목 수 |
| `coverage_ratio` | `valid_count / member_count` |
| `cap_coverage_ratio` | 유효 시총 종목의 시총 합 / 섹터 전체 시총 합 |

**규칙 AG-7 (커버리지 하한)**: `coverage_ratio < 0.80`이면 값을 표시하되 **저신뢰 표시**를 붙인다. `< 0.50`이면 값을 **null 처리**하고 "데이터 부족"으로 표시한다.

**근거**: 최신일 실측 결측률 — RS 58/2,548(2.3%), MAX52 48/2,548(1.9%), market_cap 14/2,546(0.55%). 정상 상태에서 모든 섹터가 0.95 이상이므로, 0.80 하한은 정상 운영을 방해하지 않으면서 수집 장애를 즉시 드러낸다.

### 5.6 정규화 및 composite_score

**현행 결함**: min-max 정규화(`(v−min)/(max−min)×100`)는 극단값 1개가 전체 스케일을 지배하며, `max == min`이면 전 섹터가 일괄 50.0으로 붕괴한다.

**규칙 AG-8 (순위 백분위 정규화)**: min-max를 **횡단면 순위 백분위**로 대체한다.
```
norm(v) = (rank_ascending(v) − 1) / (N − 1) × 100
```
- 극단값에 둔감하다 (단일 이상치가 스케일을 왜곡하지 못함)
- 동일 값은 평균 순위를 부여한다 (ties → average rank)
- `N == 1`이면 50.0, `N == 0`이면 빈 결과 (붕괴 상태를 명시적으로 구분)

**규칙 AG-9 (composite)**: 가중치는 현행 유지.
```
composite_score = 0.30 × norm(excess_1w) + 0.40 × norm(excess_1m) + 0.30 × norm(excess_3m)
```
어느 기간의 초과수익률이라도 null이면 **해당 섹터의 composite는 null**이며 순위 대상에서 제외한다(부분 점수 산출 금지).

**규칙 AG-10 (반올림 대칭)**: 현재·과거 composite 모두 **반올림하지 않은 값**으로 정렬·비교한다. §2.9 RK-2와 동일.

**사용자에게 보이는 변화**: composite 점수의 절대값이 바뀌므로 기존 점수와 직접 비교할 수 없다. 순위 백분위 정규화에서는 점수 분포가 균등해지고(최상위 ≈100, 최하위 ≈0), min-max에서 흔했던 "상위권 몰림"이 사라진다.

## 6. 벤치마크 규약

### 6.1 시장별 벤치마크 선택

**규칙 BM-1**: 벤치마크는 market 필터에 따라 전환된다.

| 필터 | 벤치마크 |
|------|---------|
| KOSPI | KOSPI 구성종목의 상한 적용 시총가중 집계 |
| KOSDAQ | KOSDAQ 구성종목의 상한 적용 시총가중 집계 |
| All | KOSPI + KOSDAQ 전체의 상한 적용 시총가중 집계 |

**규칙 BM-2 (방법론 일치 — 핵심)**: 벤치마크는 **섹터와 동일한 방식**으로 계산한다 — 같은 유효 유니버스, 같은 10% 상한, 같은 정규 격자 날짜, 같은 결측 처리. 등가중 섹터를 시총가중 지수와 비교하는 현행 방식이 §2.2의 상시 편향을 만든 직접 원인이다.

실측 벤치마크 값 (2026-08-11, 상한 10%):

| 기간 | KOSPI | KOSDAQ | All |
|------|-------|--------|-----|
| 1W | +1.03% | +7.54% | +1.88% |
| 1M | −1.40% | +11.01% | −0.25% |
| 3M | −14.88% | −19.85% | −15.74% |

### 6.2 지수 행과의 정합성 검증

`stock_prices`의 `Name='KOSPI'` / `'KOSDAQ'` 행은 **표시용**으로만 쓰고 초과수익률 계산의 기준으로는 쓰지 않는다. 다만 두 값의 정합성은 검증해야 한다.

**불변식 BM-3 (벤치마크 정합성)**
> 상한 없는 순수 시총가중 구성종목 집계와 지수 행의 차이가 허용오차를 넘으면 경고를 기록한다.

실측 (2026-08-11):

| 기간 | 시장 | 지수 행 | 순수 시총가중 | 차이 |
|------|------|--------|-------------|------|
| 1W | KOSPI | +1.39% | +1.49% | **−0.10%p** |
| 1W | KOSDAQ | +7.39% | +7.54% | **−0.15%p** |
| 1M | KOSPI | −6.97% | −5.31% | −1.66%p |
| 1M | KOSDAQ | +8.34% | +11.01% | −2.67%p |
| 3M | KOSPI | −19.14% | −17.17% | −1.97%p |
| 3M | KOSDAQ | −26.12% | −19.85% | **−6.27%p** |

1W에서 0.15%p 이내로 수렴하므로 **지수 행과 구성종목 집계는 같은 대상을 측정하고 있다**(원천 데이터 신뢰 가능). 기간이 길어질수록 벌어지는 것은 §3의 격자 오염과 구성종목 변동 때문으로 보인다. 허용오차 제안: **1W ≤ 0.5%p, 1M ≤ 3%p, 3M ≤ 7%p**. 초과 시 응답에 `benchmark_reconciliation_warning`을 실어 보낸다.

### 6.3 벤치마크 부재 시 처리

**규칙 BM-4 (조용한 0.0 금지)**: 벤치마크 행/데이터가 없을 때 `0.0`을 반환하는 것을 **금지**한다. 현행은 `_load_kospi_returns`가 조용히 0.0을 돌려주어 "초과수익률 = 원수익률"이 되고, 호출자는 이를 알 방법이 없다.

**규칙 BM-5 (명시적 오류 상태)**: 벤치마크 산출 실패 시
```
benchmark_return = null
benchmark_status = "unavailable"
benchmark_error   = "<사유>"
excess_return     = null
composite_score   = null   (전 섹터 순위 산출 불가)
```
화면은 "벤치마크 없음 — 초과수익률 계산 불가"를 표시하고, **원수익률만 제공**한다.

**불변식 BM-6 (날짜 창 일치)**: 섹터 수익률과 벤치마크 수익률은 **동일한 기준일과 동일한 과거 앵커 날짜**를 사용해야 한다. 응답에 두 날짜를 모두 실어 검증 가능하게 한다.

## 7. 스냅샷 유효성 규약

### 7.1 공유 기준일

**규칙 SN-1 (단일 latest-valid-date)**: 모든 엔드포인트는 다음 규칙으로 기준일을 결정한다.
```
latest_valid_date = max(정규 격자 날짜)   -- §3.3 CG-1~CG-3 적용 후
```
엔드포인트마다 `MAX(Date)`를 각자 조회하는 현행 방식은 금지한다. 미완성 주 바(CG-2)를 최신 스냅샷으로 쓸지 여부는 **전 엔드포인트가 동일하게** 결정한다.

**규칙 SN-2 (기준일 응답 포함)**: 모든 응답은 다음을 포함한다.

| 필드 | 의미 |
|------|------|
| `as_of_date` | 실제로 사용한 기준일 |
| `as_of_is_partial_week` | 진행 중인 주의 미완성 바 여부 |
| `baseline_date` | 비교 기준일(rank_change 등). 해당 없으면 null |
| `grid_version` | 정규 격자 산출 규칙의 버전 문자열 |

**불변식 SN-3 (교차 패널 일치)**: 같은 필터 조건으로 동시에 호출한 모든 엔드포인트의 `as_of_date`는 동일해야 한다. 프론트엔드는 패널 간 `as_of_date` 불일치를 감지하면 경고를 표시한다.

**규칙 SN-4 (기준일 표시)**: 화면 상단에 기준일을 항상 노출한다. 미완성 주 바인 경우 "2026-08-11 (진행 중인 주)"처럼 명시한다.

### 7.2 캐시 무효화

**규칙 SN-5**: 캐시 키에 `(as_of_date, market_filter, period, grid_version)`을 모두 포함한다. 격자 규칙이 바뀌면 `grid_version` 변경으로 전 캐시가 무효화되어야 한다.

## 9. 결측·오류 표시 정책

### 9.1 세 가지 상태의 구분

| 상태 | 의미 | 내부 표현 | 표시 | 예시 |
|------|------|----------|------|------|
| **데이터 없음** | 원천에 값이 존재하지 않음 | `null` + `reason: "missing"` | `–` (회색) | RS 행 없는 58개 종목 |
| **실제 0** | 계산 결과가 정말 0 | `0.0` | `0.00%` (일반 색) | 주간 수익률 정확히 0% |
| **계산 불가** | 입력은 있으나 산출 조건 미달 | `null` + `reason: "insufficient"` | `계산 불가` + 툴팁 | 구성종목 3개 섹터의 순위 |
| **저신뢰** | 산출되었으나 커버리지 미달 | 값 + `low_confidence: true` | 값 + ⚠ 아이콘 | `coverage_ratio` 0.5–0.8 |
| **정합성 경고** | 산출값이 검증에 실패 | 값 + `warning[]` | 값 + 경고 배지 | BM-3 허용오차 초과 |

### 9.2 금지 사항

1. 결측을 `0`으로 치환해 표시하는 것 — 사용자는 "수익률 0%"와 "데이터 없음"을 구분할 수 없다.
2. 결측을 0으로 치환하고 **분모에 남기는 것** — 평균을 조용히 왜곡한다 (§2.3 실측 사례).
3. 정규화 붕괴 시 `50.0` 표시 — 값이 있는 것처럼 보인다.
4. 벤치마크 부재 시 `0.0` 반환 (§6.3).
