## 1. 왜 이 작업이 시작됐나

Sector Analysis 화면에서 섹터 순위·버블차트·Sector Explorer가 서로 다른 숫자를 말하고, 섹터 평균을 단순 평균으로 내다 보니 시총이 작은 종목 하나가 튀면 섹터 순위가 올라가는 문제가 관찰됐다.

5개 서브에이전트로 계층별 감사를 진행한 결과 **결함 34건**이 확인됐고, 이것이 개별 버그의 모음이 아니라 **지표 정의·시간축·상태 배선이 각각 미결로 남은 결과**임이 드러났다. 그래서 코드를 고치기 전에 UI/UX 워크플로를 먼저 정립하고, 그 위에 SPEC을 세웠다.

### 확인된 결함의 성격

| 계층 | 대표 결함 |
|---|---|
| 지표 정의 | 섹터 수익률이 등가중 단순평균(주석은 "market-cap weighted"라고 적혀 있었음) · 초과수익률이 등가중 섹터를 시총가중 KOSPI에 비교 |
| 시간축 | 주중 미완성 주봉이 `INSERT OR REPLACE`로 누적되어 최근 52행이 139일(≈20주)을 덮음 |
| 유니버스 | Excel 레지스트리와 `stock_meta` 이중 소스로 게임 섹터 종목 수가 32 vs 33 |
| 상태 배선 | `crossTabParams` 하나가 "공유 선택 상태"와 "화면 이동 의도"를 겸함 |
| 조용한 실패 | 결측 RS를 0으로 치환하고 분모에 남김 · 벤치마크 부재 시 0.0 반환 |

이 모든 것이 **오류 없이 그럴듯한 숫자로 렌더링**됐다는 점이 핵심이다.

## 4. 확정된 제품 결정 (재논의 대상 아님)

| 항목 | 결정 |
|---|---|
| 섹터 수익률 | 시총가중 + 종목별 상한 **10%** (`cap_eff = max(0.10, 1/N)`), 최소 구성 5종목 |
| RS 평균 | **등가중 유지** — RS는 이미 백분위라 시총가중이 의미를 왜곡. 수익률과 가중 방식이 의도적으로 다르며 열 헤더에 병기 |
| 커버리지 | 0.80 미만 경고 / 0.50 미만 null, 지표별 dict + 최상위 최소값 |
| 시장 토글 | 집계 시점 실필터, 벤치마크도 시장별 전환 |
| Stage | 주봉 Weinstein 단일화, 일봉 근사 분류기 폐기 |
| 기준 시점 | 진행 중인 주를 표시하되 "진행 중 (N일치)" 배지 + 배경 구분 |
| RRG | 롤링 정규화 없이 `RS_line = sector/benchmark × 100` — **100이 문자 그대로 벤치마크**(표준 JdK와 다름). 시점별 시총 역산 + 수익률 체인 지수 |
| 거래대금 | 기간 토글과 같은 창 합산 + **기간별 고정 눈금 사다리** (1W 100억/1,000억/1조 · 1M 500억/5,000억/5조 · 3M 1,000억/1조/10조) |

ORDER BY Date DESC LIMIT ?`로 조회해 `weeks=12`가 ①이 7개 소비자에서 고친 것과 같은 결함(약 36일치만 반환)을 그대로 지니고 있으나, 이 3-계층 로드맵 범위 밖이며 현재 출하 중인 상태로 남아 별도 SPEC이 필요하다 (`SPEC-SECTOR-GRID-001/progress.md` §Residual-risk 등재) |

## 7. 반드시 알아야 할 사실

**1. `weekly.py`의 positional INSERT는 ① M3에서 이미 column-name으로 마이그레이션됐다 (완료).**
`my_chart/db/weekly.py:164`(stock_prices)과 `:186`(relative_strength)는 이제 `INSERT OR REPLACE INTO ... ({column_list}) VALUES ({placeholders})` 형태의 컬럼명 기반이다. `:156`과 `:180`에 남은 `VALUES (?` 문자열은 실행 코드가 아니라, positional을 **쓰지 않는 이유**를 설명하는 `@MX:REASON` 주석이다. `daily.py:276`은 [lessons #8](../../.claude/) 의 1.3M 행 부패 사고 후 이미 먼저 마이그레이션됐고, ① M3가 `weekly.py`의 나머지 두 지점을 같은 방식으로 옮겼다. `AC-SGR-010`이 **legacy-ALTER 라운드트립 + positional 경로에서 시프트가 발생함을 대조 단언**하는 회귀 테스트로 이 상태를 고정한다. 감사가 "이 작업에서 가장 잘 된 부분"으로 꼽은 항목이므로 **AC-SGR-010과 이 마이그레이션 자체는 수정하지 말 것.**

**2. `SMA40`·`MAX52`·`CHG_*`는 DB 행이 아니라 수집 시점 원천 시계열에서 계산된다.**
200종목 표본에서 저장 `SMA40`이 "DB 최근 40행 평균"과 일치한 것은 22건뿐이다. 따라서 주봉 중복 바 오염은 **Stage 분류에 영향이 적고**, 깨진 것은 DB 행을 세는 계산(히스토리·RRG·rank_change 기준일)뿐이다. 초기 감사의 "SMA40이 실제 22주라 Stage 전제가 붕괴했다"는 검증 결과 **사실이 아니다.**

**3. frozen 픽스처 수치는 `as_of 2026-08-11` 기준이다.**
라이브 DB가 갱신되면 `GRID acceptance.md §3` / `AGG acceptance.md §8`의 고정 수치를 재측정해야 한다. 이미 드리프트가 시작됐다. 재개 전 최신일을 먼저 확인할 것. — ①은 프로즌 픽스처가 커밋된 정적 자산이고 게이팅 AC가 더 이상 라이브 DB 상태에 의존하지 않으므로 이 드리프트 경고의 대상에서 제외된다. **②의 골든 baseline은 아직 미캡처**이므로 이 경고는 ② 착수 시 그대로 유효하다.

## 8. 구현 후 나타날 "고장처럼 보이지만 올바른" 변화

전부 AC에 **기대값으로 고정**돼 있다. 회귀로 오인해 되돌리면 안 된다.

| 변화 | 이유 |
|---|---|
| 섹터 순위가 크게 뒤바뀜 (평균 3.5계단, 반도체 26→29, 헬스케어 8→3) | 등가중 → 시총가중 **정의 변경** |
| 1W 초과수익률 양수 섹터 29/29 → **18/29** | 벤치마크 방법론 일치. 이전엔 구조적 양(+) 편향 |
| 52주 신고가 99개(4.0%) → **56개(2.2%)** | `MAX52`가 Close 기준이라 91.7% 종목에서 실제 고점보다 낮았음 |
| RS 평균 상승 (방산 45.6 → 51.3) | 결측 58종목을 0으로 치환해 분모에 남기던 처리 제거 |
| 복합점수 절대값 변경 | min-max → 순위 백분위 정규화. 이전 점수와 직접 비교 불가 |
| KOSPI 필터에서 디스플레이·스마트폰 사라짐 | 표본 4종목 < 최소 5. 하단 제외 목록에 사유와 함께 표시됨 |
| RRG 사분면 편중 | 100이 이제 벤치마크. 시장 전체가 강하면 다수가 주도에 몰리는 것이 정상 |
| RRG 궤적 단축 | 상수 100 패딩 구간 미발행 |

**릴리스 노트에 반드시 반영할 것.**
