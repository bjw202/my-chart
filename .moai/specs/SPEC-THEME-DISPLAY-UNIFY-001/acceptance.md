> 대상: `frontend/src/components/ThemeAnalysis/ThemeRankingTable.tsx`
> 검증 위치(신규): `frontend/src/components/ThemeAnalysis/__tests__/ThemeRankingTable.display.test.tsx`

## §A 대조 단언 설계 규약 [HARD]

본 SPEC의 AC는 lessons.md **#9**의 판정 기준을 따른다. 그 기준의 핵심은 한 문장이다 — **대조 단언은 "작성했는가"가 아니라 "되돌렸을 때 RED를 관측했는가"로 판정한다.**

### §A.1 run 단계가 지켜야 할 규칙

1. **되돌림 실증 의무**: §B의 대조 단언을 GREEN으로 기록하기 전에, `ThemeRankingTable.tsx`를 지역 포맷터 3종 버전으로 되돌린 사본을 만들어 테스트를 실행하고 **실패 출력을 축자 캡처**한다. 그 뒤 트리를 복원하고 `git status --short`로 복원을 증명한다. 실증하지 못한 항목은 GREEN이 아니라 **미검증(Gaps)** 으로 기록한다.
2. **양변 출처 분리**: 모든 단언의 한 변은 **프로덕션 경로**에서 와야 한다 — 즉 `render(<ThemeRankingTable ... />)` 결과의 DOM 텍스트여야 한다. 반대 변은 **프로즌 리터럴**이다.
3. **정본 상수 import 금지(대조 단언 한정)**: 대조 단언에서 `MISSING_TEXT`를 import해 비교하지 **않는다**. 상수를 import하면 정본 값이 바뀌어도 단언이 함께 따라가 글리프 고정이 풀린다. 반드시 리터럴 `'–'`로 못박는다. (정본 드리프트는 AC-TDU-014가 따로 잡는다.)
4. **부분 일치 금지**: `toContain`으로 부분 문자열을 확인하지 않는다. 전체 문자열 **등식**을 쓴다. 선례 — `MetricTextParity.m7.test.tsx:122`가 `toContain('RS 평균: 60<br/>')`처럼 **구분자까지 포함해 앵커**한 이유는 `'60' ⊂ '60.0'`이 공허한 단언이었기 때문이다. 같은 함정이 여기서는 `'-' ⊂ '–'`가 아니라 **`'62.5%' ⊂ '+62.5%'`** 형태로 나타난다.
5. **부등식·부분집합 금지**: 개수 단언은 `>= n`이 아니라 `=== n`(프로즌)으로 쓴다.

### §A.2 대조(contrast)와 불변(invariance)의 구분 [HARD]

두 종류를 섞어 기록하는 것이 #9가 지적한 실패의 절반이다. 본 SPEC은 이를 라벨로 강제 분리한다.

| 분류 | 정의 | 되돌렸을 때 | 기록 방식 |
|---|---|---|---|
| **대조** | 마이그레이션이 실제로 일어났음을 반증 가능하게 증명 | **RED여야 함** | §B. 되돌림 실증 필수 |
| **불변** | 마이그레이션이 정상값 표시를 바꾸지 않았음을 고정 | **GREEN(정상)** | §C. 되돌림 실증 대상 아님 |

§C 항목을 "대조 단언"으로 보고하는 것은 금지한다. §C는 회귀 방지 장치이지 대조가 아니며, 되돌려도 통과하는 것이 **정상**이다. 이 사실을 숨기면 #9의 항진명제 보고와 같은 결함이 된다.

## §B 대조 단언 (되돌림 시 RED — 실증 의무)

### AC-TDU-001 — 모멘텀 결측 글리프 [대조]
**Given** `momentum_score`가 `undefined`인 테마 1건
**When** `ThemeRankingTable`을 렌더한다
**Then** 모멘텀점수 열 `<td>`의 `textContent`가 **정확히** `'–'`(en dash 한 글자)와 같다.
**되돌림 예상**: `formatMomentum`이 `'-'`(U+002D)를 반환 → 불일치 → RED.

### AC-TDU-002 — 상승비율 결측 글리프 [대조]
**Given** `breadth_ratio`가 `undefined`인 테마 1건
**When** 렌더한다
**Then** 상승비율 열 `<td>`의 `textContent`가 **정확히** `'–'`와 같다.
**되돌림 예상**: `formatBreadth`가 `'-'` 반환 → RED.

### AC-TDU-003 — 지표 셀 구조 채택 [대조]
**Given** 테마 1건(값 유무 무관)
**When** 렌더한다
**Then** `container.querySelectorAll('[data-testid="metric-cell"]').length`가 **정확히 `4`**와 같다 (등락률·3일등락률·모멘텀점수·상승비율).
**되돌림 예상**: 지역 포맷터는 `<span data-testid>`를 만들지 않음 → `0` → RED.
**주의**: `>= 1`이 아니라 `=== 4`다. 부분 채택(예: 3개만 이관)도 RED로 잡기 위함이다.

### AC-TDU-004 — 비유한값 접기 [대조 · 이중 판별]
**Given** `change_pct`가 `Infinity`인 테마 1건
**When** 렌더한다
**Then** 등락률 열 `<td>`의 `textContent`가 **정확히** `'–'`와 같다.

이 AC는 **두 가지 실패를 동시에 판별**한다.

| 상태 | 렌더 결과 | 판정 |
|---|---|---|
| 올바른 구현(`toMetricValue` 경유) | `–` | PASS |
| 되돌림(지역 포맷터) | `-` | RED |
| **불완전 구현**(`MetricCell`에 날값 전달) | `+Infinity%` | **RED** |

세 번째 행이 이 AC의 존재 이유다. §1.3(a)에서 계측한 대로 `resolveState`는 `Number.isNaN`만 보므로 `Infinity`를 정상값으로 통과시킨다. REQ-TDU-002(`toMetricValue` [HARD])를 기계적으로 강제하는 유일한 단언이다.

### AC-TDU-005 — 런타임 null 내성 [대조]
**Given** `change_pct`가 런타임에 `null`인 테마 1건 (`null as unknown as number`로 주입 — TS 필수 타입을 우회해 **런타임** 경로를 재현)
**When** 렌더한다
**Then** 렌더가 예외를 던지지 않고, 등락률 열 `<td>`의 `textContent`가 **정확히** `'–'`와 같다.
**되돌림 예상**: `isFinite(null) === true`이므로 가드를 통과해 `null.toFixed(2)` 도달 → `TypeError` → 렌더 실패 → RED.
**주석 의무**: 이 테스트에는 "`change_pct`는 TS상 필수지만 API 응답이 `as` 캐스팅으로 검증 없이 통과하므로(`themes.ts:70`) 런타임 `null`이 배제되지 않는다"는 근거를 주석으로 남긴다. 주석이 없으면 후속 작업자가 "불가능한 케이스"로 오해해 삭제한다.

### AC-TDU-006 — 대표종목 결측 글리프 [대조]
**Given** `top_stocks_preview`가 `undefined`인 테마 1건
**When** 렌더한다
**Then** 대표종목 열 `<td>`의 `textContent`가 **정확히** `'–'`와 같다.
**되돌림 예상**: `?? '-'` → RED.

### AC-TDU-007 — 잔여 집합 동등 (전 열 일괄) [대조 · 최강]
**Given** `theme_name = '테스트테마'`이고 나머지 5개 필드가 전부 결측인 테마 1건
**When** 렌더한다
**Then** 그 행의 `<td>` 6개 `textContent`를 순서대로 모은 배열이 **프로즌 리터럴 배열과 정확히 같다**:

```
['테스트테마', '–', '–', '–', '–', '–']
```

**픽스처 주입 방식 [HARD]**: 5개 필드 중 `change_pct`·`change_pct_3d`는 TS상 **필수**이므로, AC-TDU-005와 동일하게 `null as unknown as number`로 주입해 결측 상태를 만든다. 이 지시가 없으면 run 단계가 타입 오류를 피하려고 픽스처를 "결측 3개"로 약화시키게 되고, 그러면 아래 잔여 집합 동등의 강도가 무너진다 — 프로즌 배열이 6칸이 아니라 4칸만 구속하게 되어, 필수 타입 두 열의 누락을 잡지 못한다.

**설계 의도**: #9는 "배제 정규식 체인보다 **잔여 집합 동등**이 강하다"고 명시한다. 개별 열 단언(AC-001·002·004·006)은 지정한 열만 보므로 **누락된 열을 잡지 못한다**. 이 AC는 행 전체를 프로즌 배열로 고정하므로, 어느 한 열이라도 `'-'`로 남으면 RED다. run 단계가 5개 지점 중 4개만 고치는 부분 이행을 구조적으로 차단한다.
**되돌림 예상**: 5개 원소가 전부 `'-'` → RED.

### AC-TDU-008 — 신뢰도 상태 무합성 [대조]
**Given** 테마 **1건** — 4개 지표 중 일부는 정상값, 일부는 결측 (예: `change_pct = 1.5`, `change_pct_3d = -2.5`, `momentum_score = undefined`, `breadth_ratio = 0.625`)
**When** 렌더한다
**Then** 모든 `[data-testid="metric-cell"]`의 `data-state` 속성값을 모은 집합이 `{'ok', 'missing'}`의 **부분집합**이며, `'low-confidence'` / `'warning'` / `'insufficient'`를 **하나도 포함하지 않는다**.
**되돌림 예상**: `data-state` 속성 자체가 없어 수집 결과가 빈 집합 → 아래 동반 단언에서 RED.

**동반 단언 필수 [HARD]**: 빈 집합은 어떤 집합의 부분집합이므로 위 단언만으로는 되돌림 시 **통과해 버린다**(공허 참 — #9의 항진명제 유형 3). 따라서 수집한 `data-state` 개수가 **정확히 4**임을 함께 단언한다. 이 AC의 대조 강도는 **전부 이 동반 단언에 실려 있다** — 없으면 이 AC는 대조 단언이 아니다.

**Given이 1건인 이유 (v0.2.0 정정)**: v0.1.0은 Given을 "테마 2건"으로 두고 개수를 `=== 4`로 고정했다. 한 행이 4개 셀을 렌더하므로 2건이면 **8개**이고, 따라서 **올바른 구현이 실패**한다. 그 상태에서 run 단계가 택할 가장 쉬운 수선은 개수 단언을 느슨하게 푸는 것인데, 그러면 이 AC의 대조 강도가 통째로 사라진다 — 고쳐야 할 결함이 **가드를 제거하는 방향으로** 유도되는 형태였다.

1건으로 고정하는 편을 택한 이유는 산술을 맞추는 방법이 둘(1건+`=== 4` / 2건+`=== 8`)이기 때문이다. **`4`는 AC-TDU-003의 프로즌 개수와 같은 수**이므로, 한쪽만 고쳐도 다른 쪽과 어긋나 즉시 드러난다. `8`을 쓰면 두 상수가 독립적으로 표류할 수 있다.

정상값과 결측이 **섞인** 1건이어야 한다는 점도 구속이다 — 전부 정상이면 수집 집합이 `{'ok'}`뿐이라 `missing` 경로가 검사되지 않고, 전부 결측이면 그 반대다.

## §C 불변 단언 (되돌려도 GREEN — 회귀 방지용, 대조 아님)

> 이 절의 항목은 **되돌림 실증 대상이 아니다**. 마이그레이션 전후 표시가 바이트 동등임을 고정하는 것이 목적이며, 되돌렸을 때 통과하는 것이 정상이다. 이를 대조 단언으로 보고하지 않는다(§A.2).

### AC-TDU-009 — 양수 등락률 [불변]
**Given** `change_pct = 1.5` **When** 렌더 **Then** 등락률 셀 `textContent === '+1.50%'` (전체 등식).

### AC-TDU-010 — 음수 등락률 [불변]
**Given** `change_pct = -2.5` **When** 렌더 **Then** `textContent === '-2.50%'`.

### AC-TDU-011 — 0 등락률 [불변]
**Given** `change_pct = 0` **When** 렌더 **Then** `textContent === '0.00%'` — 부호 없음. `0 > 0`이 거짓이므로 `+`가 붙지 않는 현행 거동을 고정한다. ER-2("실제 0"과 "결측"은 구분되어야 함)의 Theme측 확인이기도 하다.

### AC-TDU-012 — 상승비율 3축 동시 고정 [불변 · 핵심]
**Given** `breadth_ratio = 0.625` **When** 렌더 **Then** 상승비율 셀 `textContent === '62.5%'` (전체 등식).

D2의 세 축을 한 단언이 동시에 구속한다. 잘못된 구현별 실패 양상:

| 잘못된 구현 | 렌더 | 판정 |
|---|---|---|
| `percent1` 채택 | `+62.5%` | FAIL(부호) |
| `pct0` 채택 | `63%` | FAIL(정밀도) |
| ×100 누락 | `0.6%` | FAIL(단위) |

**부분 일치 금지가 특히 중요한 지점**: `toContain('62.5%')`로 쓰면 `'+62.5%'`도 통과해 부호 회귀를 놓친다(§A.1 규칙 4).

### AC-TDU-013 — 모멘텀점수 [불변]
**Given** `momentum_score = 3.14159` **When** 렌더 **Then** `textContent === '3.14'` — 단위 접미사 없음.

### AC-TDU-014 — 정본 상수 드리프트 감시 [불변]
**Given** `MetricCell.tsx`에서 `MISSING_TEXT`를 import
**When** 값을 확인한다
**Then** `MISSING_TEXT === '–'`.
**목적**: §B의 대조 단언들은 리터럴로 못박혀 있으므로(§A.1 규칙 3), 정본 상수가 바뀌면 그것들이 한꺼번에 RED가 된다. 이 단언은 그때 **원인이 Theme 구현이 아니라 정본 변경임**을 즉시 가리키는 진단용이다.

### AC-TDU-015 — 정렬·색상 거동 보존 [불변]
**Given** 테마 2건
**When** 등락률 헤더를 클릭한다
**Then** `onSort`가 `'change_pct'`로 정확히 1회 호출되고, 등락률 `<td>`의 인라인 `background`가 비어 있지 않다(`getChangePctColor` 유지 — REQ-TDU-008).

**F7 주의**: 라이브 확인은 반드시 **dev 서버 재시작 후** 수행한다 — Fast Refresh가 낡은 모듈을 보존해 변경이 미반영으로 보이는 사례가 이 프로젝트에서 실측된 바 있다.

**F2가 이 SPEC의 중심 게이트다.** F1만 통과하고 F2를 실증하지 못한 항목은 §Gaps에 기록하며, "대조 단언 8종 GREEN"으로 보고하지 않는다.
