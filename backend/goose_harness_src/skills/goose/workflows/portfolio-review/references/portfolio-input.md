# 보유자산 상담 입력과 계산 규약

## 상담에서 먼저 확인할 내용

사용자가 제공한 종목·보유 수량·주당 평균 매입가·통화·현금으로 현재 상태부터 계산합니다. 평균 매입가를 총 매입금액으로 해석하지 않습니다. 목적, 투자 기간, 예정 인출·생활비, 비상자금, 손실을 감내할 수 있는 금액과 낙폭, 추가 납입, 부채·신용 사용 여부, 매매 제한, 계좌의 세금·비용 조건은 답변받은 범위에서 기록합니다. 연령이나 보유 종목만으로 위험 성향을 추정하지 않습니다. 미답변 항목이 있더라도 확인 가능한 현황 계산은 진행하고 개인별 목표 비중을 확정하지 않습니다.

일부 보유 주식만 받았으면 `coverage=partial`입니다. `full`은 사용자의 제공 범위 선언이며 금융자산·부동산·부채를 모두 검증했다는 뜻이 아닙니다. 비공개 계좌번호·인증정보는 계산에 필요하지 않습니다. 실제 계좌 입력·결과는 저장소의 예시·테스트에 넣지 않습니다.

자산배분을 판단할 때 투자 기간과 위험 감수 수준을 확인하고, 리밸런싱은 기존 목표 배분과 현재 배분의 차이를 살펴보는 과정으로 설명합니다. [SEC Investor.gov의 자산배분·분산·리밸런싱 안내](https://www.investor.gov/introduction-investing/getting-started/asset-allocation)를 2026-10-16에 직접 열람하여 이 상담 항목의 일반 원칙을 확인했습니다. 특정 비중이나 개인별 거래 지시의 근거로 전용하지 않습니다.

## 실행

스킬 폴더에서 실행합니다. Python 3 표준 라이브러리만 사용하며 네트워크·증권사 연결·주문 기능은 없습니다.

```sh
python3 scripts/portfolio_calc.py input.json --output calculation.json
python3 -m unittest discover -s tests -v
```

## 최소 예시 — 모두 가상 데이터

아래 종목과 시장은 실제 종목이 아닙니다. 가격 출처도 가상 예시입니다.

```json
{
  "base_currency": "KRW",
  "as_of": "2026-10-16T09:00:00+09:00",
  "coverage": "partial",
  "max_price_age_days": 3,
  "max_fx_age_days": 3,
  "holdings": [{
    "id": "synthetic-a",
    "ticker": "SYNTH-A",
    "market": "FICTIONAL",
    "quantity": "10",
    "average_cost": "100",
    "cost_currency": "USD",
    "current_price": "120",
    "price_currency": "USD",
    "price_as_of": "2026-10-15T16:00:00-04:00",
    "price_source": "synthetic demonstration; not live data",
    "issuer_id": "fictional-issuer-a",
    "sector": "fictional-sector"
  }],
  "cash": [{"id": "cash-krw", "currency": "KRW", "amount": "390000"}],
  "fx_rates": [{
    "currency": "USD",
    "rate_to_base": "1300",
    "as_of": "2026-10-15T09:00:00+09:00",
    "source": "synthetic demonstration; not live data",
    "verified": true
  }],
  "targets": [
    {"id": "synthetic-a", "weight_percent": "60"},
    {"id": "cash-krw", "weight_percent": "40"}
  ],
  "estimated_cost_base": "1000"
}
```

## 입력 필드

| 필드 | 규약 |
|---|---|
| base_currency | 세 글자 통화 코드. 전체 계산 결과의 기준 통화입니다. |
| as_of | 계산 기준 시각. ISO 8601 날짜 또는 시간대가 포함된 시각. 시간대 없는 시각은 거부합니다. 날짜만 주면 UTC 자정입니다. |
| coverage | partial 또는 full. 사용자가 제공한 자산 범위에 대한 선언입니다. |
| holdings | 현물 롱 포지션 배열. quantity와 average_cost는 필수이며 음수를 허용하지 않습니다. 공매도·신용·파생·부채 포지션은 지원하지 않습니다. |
| id / ticker / market | 모든 자산·현금 id는 고유해야 합니다. 동일 ticker+market의 여러 매입건은 수량과 가중 평균 단가로 먼저 합칩니다. |
| average_cost / cost_currency | 주당 평균 매입가와 그 통화입니다. 수수료가 포함된 평단인지 사용자 자료에 기록합니다. |
| current_price / price_currency | 주당 가격과 통화. 미확인 가격은 null. null을 0으로 대체하지 않습니다. 0은 명시적으로 제공한 가격에만 허용합니다. |
| price_as_of / price_source | 가격이 있을 때 필수. 실제 시세 기준 시각과 확인 출처를 넣습니다. 기준 시각 이후 가격을 입력하면 실패합니다. |
| issuer_id / sector | 선택 사항. 자료로 확인한 발행기업 공통 id와 업종을 넣습니다. 같은 회사의 서로 다른 상장 종목은 같은 issuer_id로 합산합니다. 모르면 생략하고 매핑 미완료로 남깁니다. |
| cash | id·currency·amount를 가진 현금 배열. 알려진 현금이 없다면 빈 배열. 누락된 현금을 0으로 안다고 주장하지 않습니다. |
| fx_rates | 외화 1단위당 기준 통화 금액(rate_to_base), 기준 시각, 출처, verified=true. 수집 에이전트가 원자료를 대조했을 때만 verified=true를 넣습니다. 계산기가 출처의 진위를 확인한다는 뜻은 아닙니다. 기준 통화 환율은 입력하지 않습니다. |
| max_price_age_days / max_fx_age_days | 선택 사항. 사용자가 정한 허용 경과일. 없으면 경과 시간만 제시하고 최신성은 not_assessed로 기록합니다. 거래일이 아닌 실제 경과일입니다. |
| targets | 선택 사항. 사용자가 제공·확인한 목표만 넣습니다. 모든 보유자산과 현금 id를 빠짐없이 포함하며 0%도 명시합니다. 합은 정확히 100%여야 합니다. 새 자산을 넣으려면 수량 0, 확인된 가격과 메타데이터로 먼저 holdings에 등록합니다. |
| estimated_cost_base | 선택 사항. 사용자가 제공한 시나리오 총 예상 비용. 입력되지 않으면 수수료·세금 0원으로 가정하지 않고 비용 후 실행 가능성은 null로 남깁니다. 정확한 세액·수수료 계산 기능은 아닙니다. |

금액·수량은 정확한 십진 문자열 사용을 권장합니다. NaN·Infinity·음수·중복 자산은 거부합니다. 계산은 Decimal 50자리 정밀도로 수행하고 출력은 소수점 여섯 자리 문자열로 반올림합니다. 대형 기관 원장이나 극단적 정밀도·규모 입력을 위한 임의정밀 원장 시스템은 아닙니다.

## 산출물 해석

- `totals.cost_basis_base`는 주식 매입원가 합계, `market_value_base`는 주식 평가액과 현금 합계입니다. 투자 평가손익률의 분모에는 현금을 넣지 않습니다.
- `unrealized_pnl_base`는 평가액에서 매입원가를 뺀 미실현 손익이며 실현손익·배당·세금을 포함한 총수익률이 아닙니다. 원가가 0이면 손익률은 null입니다.
- 외화 매입원가도 제공한 동일 스냅샷 환율로 환산합니다. 매수일 실제 환율·현금흐름을 받지 않으므로 환차손익을 포함한 실제 원화 투자수익률로 설명하지 않습니다.
- 하나라도 평가 가격·필요 환율이 없으면 전체 평가액과 비중은 null입니다. `known_*_subtotal`과 `known_subset_allocation_percent`는 확인된 부분집합만의 수치라고 표시합니다. 리밸런싱은 중단됩니다. 원가 환율만 빠진 경우 평가 비중은 계산하되 전체 손익은 null입니다.
- `sector_concentration`·`issuer_concentration`은 확인된 업종·발행사만 합산합니다. 분모에는 현금이 포함됩니다. 매핑하지 못한 평가액을 별도로 노출하고 높은 집중도가 자동으로 잘못된 배분임을 뜻한다고 단정하지 않습니다.
- `rebalance`는 사용자 목표에 대한 목표금액·차이와 정수 주식 수량의 설명용 시나리오입니다. 차액/가격의 절댓값을 내림하므로 소수 보유 주식과 현금 잔여가 남습니다. 주문 파일이나 매매 지시가 아닙니다.
- 시나리오에서는 가상 매도대금이 모두 가용 현금이 된 후 매수한다고 가정합니다. 통화별 현금 환전, 결제일, 거래량·호가, 매매 제한은 모델링하지 않습니다. 외화 현금을 합친 산술적 가능성이 실제 즉시 매매 가능성을 뜻하지 않습니다.
- 목표는 비용 차감 전 평가액 기준입니다. 비용·정수주 반올림 때문에 목표 현금 비중이 정확히 달성되지 않을 수 있습니다. 비용 후 현금, 목표 현금 차이를 같이 보여주고 음수 가용 현금을 실행 가능하다고 설명하지 않습니다.

최종 상담은 **제공 범위와 기준일 → 보유 현황과 평가손익 → 기업·업종·통화 집중과 근거 → 사용자 목적과 제약 → 유지/추가 납입/목표 차이 시나리오 → 확인해야 할 조건**의 흐름으로 작성할 수 있습니다. 단일 종목 보고서의 10개 장이나 오피니언 12문단을 억지로 적용하지 않습니다. 뉴스·기업 전망이 필요하면 종목 분석 스킬의 직접 열람·출처 장부를 연계하며 계산 결과만으로 기업 전망을 생성하지 않습니다.
