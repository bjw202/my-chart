# 종목 심층 분석과 최종 보고서

[조사 계약](references/research-contract.md), [역할 계약](references/agent-team.md), [보고서 기준](references/report-standard.md)을 읽습니다. 입력은 대상기업·기준일·요청범위이며 전 단계 산출물이 있으면 함께 받습니다.

- standalone: 공시·재무, 뉴스, 산업·경쟁 조사 역할을 구성합니다. earnings-review, event-impact, peer-compare를 필요한 범위의 leaf로 연결하고 공통 원장을 통합합니다. fact-check로 독립 검토 후 수정합니다.
- render: 전달된 원장·검토 결과로 편집합니다. 해결되지 않은 중요 주장이나 새 문장이 생기면 해당 주장만 재검토에 돌립니다. 보고서 생성 과정이 조사 완료 상태를 임의로 올리지 않습니다.
- leaf: 담당 보고서 또는 편집 결과만 반환하고 총괄 스킬을 재호출하지 않습니다.

[입력 형식](references/report-input.md)에 맞춰 구조화 데이터를 만들고 scripts/render_report.py를 사용합니다. 결과를 별도 기업/기준일 경로에 저장합니다. 보고서의 숫자·판단·날짜는 입력에서 가져오며 과거 사례를 그대로 재사용하지 않습니다. Markdown 원문·HTML·구조화 입력·출처/계산·검토 기록을 함께 전달합니다.

## 설치 후 결과 비교에서 도출한 품질 게이트

1. 12문단×5문장은 최소 형식입니다. 승인된 상세 칼럼의 밀도는 보통 문단당 7~9문장·450~700자 수준이었으며, 문장을 잘게 나누거나 같은 경고를 반복해 채우지 않습니다. 각 문단에 논지, 구체적 근거, 작동 원리, 가장 강한 반론, 투자자의 다음 확인 조건을 연결합니다. 더 짧게 끝내는 것이 타당하면 편집 검토에 이유를 기록합니다.
2. 관심종목 편입은 조사 우선순위입니다. 적정가격을 계산하지 못했다는 이유만으로 자동 관망하지 않습니다. 성장의 관찰 가치·반증·정보 공백으로 조사 우선순위를 결정하고 가격 매력 및 개인 비중 판단은 별도로 둡니다. 이전 샘플과 판단이 달라도 오류가 아니며, 같은 판단을 재현하려고 근거를 맞추지 않습니다. `opinion.decision_scope`는 `research_priority`로 기록합니다.
3. 각 담당자의 중요한 긍정·반대 논거를 본문과 오피니언의 문단 ID에 연결한 coverage 표를 `editorial-review.md`에 남깁니다. 제외하면 이유를 쓰고, 자료가 존재하는데 미확인으로 끝내지 않습니다. 자사주는 결의·개별 체결·취득 완료·소각 완료를 분리해 KIND/DART의 후속 기록을 확인합니다. 과거 보고서는 탐색의 출발점이며 이번 직접 열람으로 승격하지 않습니다.
4. 분기 추이·이익률·이익-현금 연결 등 핵심 질문에 맞는 재무 도해를 선택합니다. 검증한 기간이 충분한데 두 시점만 남겨 흐름을 지우지 않습니다. 자료가 부족하면 이유를 밝히며 개수를 채우기 위해 차트를 만들지 않습니다.
5. 단순 구조 PASS는 편집 품질 PASS가 아닙니다. `editorial_review`에 `argument_depth`, `decision_scope`, `material_coverage`, `visual_review` 각각의 `{status:reviewed|pending|limited, evidence:실제 검토 기록}`를 남깁니다. 실제 브라우저 확인이 없으면 visual_review를 reviewed로 쓰지 않습니다. 렌더러의 editorial_quality 경고는 별도 감수 대상으로 넘깁니다. 미완료 조사·감수는 사유만 붙여 최종 제출하지 않으며, 현재 입력과 화면에 대한 최종 감사 계약을 통과해야 합니다. 이 선언 자체는 독립 감사 증명이 아닙니다.
6. 중요한 숫자와 판단은 문단의 `highlights`에 원문 그대로 지정합니다. 전체 문장에 태그를 넣지 않습니다. 생성기는 안전하게 강조를 출력하며, 단일 HTML의 JSON 다운로드도 자체 내장해 폴더가 분리되어도 사용할 수 있게 합니다.

## 최종본 생성 조건

[최종 감사 계약](../fact-check/references/delivery-audit.md)을 적용합니다. 일반 렌더는 감사 대기 초안입니다. 조사·기간·최신성 부족이나 미완료 화면 감수는 최종 제출을 막습니다. 경고를 이유 설명만으로 넘기던 이전 규칙은 이 규칙으로 대체합니다. 수정된 입력은 새 초안과 감수 기록이 필요하며 `--final`이 성공한 결과만 최종본으로 전달합니다.
