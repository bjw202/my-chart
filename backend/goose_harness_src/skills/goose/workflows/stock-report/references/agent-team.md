# 역할별 실행·소유권

## 구스 에이전트 애널리스트 (goose)
요청을 `workflow-map.json`에 대응시키고 실행 계획을 세웁니다. 종목·기간·입력·사용자 제약·출력 위치를 전달합니다. 각 작업에 한국어 역할명과 책임 파일을 지정합니다. 상태는 `대기 / 자료 읽는 중 / 분석 중 / 검증 중 / 수정 중 / 완료 / 확인 제한`이며 실제 작업 사건에만 바꿉니다. 독립 역할 작업은 가능한 환경에서 분업합니다. 동일 파일을 여러 작업자에게 쓰게 하지 않고 메모를 편집 담당이 통합합니다.

| 역할 | 관련 스킬 | 입력 | 책임 결과물 | 검증 초점 |
|---|---|---|---|---|
| 공시·재무 분석 에이전트 | earnings-review | 대상·기준일·공시 경로 | finance-notes.md, 담당 sources/metrics 조각 | 연결·분기·단위, 주석·검토의견, 손익↔현금 |
| 뉴스 조사 에이전트 | event-impact | 대상·기준일·쟁점 | news-notes.md, 사건·출처 조각 | 원 언론, 사건일, 회사 반론, 후속 정정 |
| 산업·경쟁사 분석 에이전트 | peer-compare | 사업 범위·비교 대상 | industry-notes.md, 비교 지표 조각 | 회계기간·부문범위, 공급·계약·고객 투자 |
| 보유자산 상담 에이전트 | portfolio-review | 사용자 입력·목표·시세·환율 | portfolio-analysis.json, 상담 메모 | 원가·비중·현금, 목표 조건·부분계좌 |
| 팩트체크 에이전트 | fact-check | 주장·출처·계산·초안 | review.md, 결함/수정 상태 | 독립 원문 대조, 반증 누락, 요약 과장 |
| 보고서 편집 에이전트 | stock-report | 통합 메모·원장·검토 | report.md, report-input.json, report.html | 승인한 디자인·존대 문체, 출처와 결론 일치 |

역할별 메모 계약: `{role, task, status, claims, metrics, sources, counterarguments, limitations, output_paths}`. 총괄이 ID 충돌을 제거하고 공통 원장으로 합칩니다. 자산 상담 입력 전체를 뉴스 담당에게 전달하지 말고 필요한 종목명만 전달합니다.

## 스킬 체이닝 규칙
자동 라우팅은 사용자의 요청 범위 안에서 조사·분석·로컬 보고서 작성을 연결합니다. 환경에 실제 스킬 호출 도구가 있으면 사용하고, 없으면 해당 SKILL.md를 읽어 절차를 실행합니다. 스킬 호출 기능이 없는데 호출 성공으로 표시하지 않습니다. 하위 작업에는 `execution_mode=leaf`, `run_id`, `requested_scope`, `input_paths`, `output_path`를 전달합니다. leaf는 다른 스킬·에이전트를 호출하지 않고 요청된 phase의 담당 결과만 반환합니다. 단계 분기와 후속 호출은 총괄만 수행합니다. standalone으로 직접 요청된 스킬은 실행 지도의 해당 흐름만 한 번 실행하는 임시 총괄이 될 수 있습니다. 최종 편집은 `execution_mode=render`로 검토된 결과를 받습니다. 단독 호출은 같은 스킬의 standalone 절차로 수행합니다.

병렬 도구/에이전트가 없으면 역할별로 순차 실행하고 `단일 실행자·역할별 순차 검토`라고 표시합니다. 독립 재검토가 아닌 자기 검토를 독립 감사라고 부르지 않습니다. 네이티브 에이전트 카드의 표시명이 한국어로 바뀐다고 보장하지 않습니다. 사용자에게 보여주는 진행표·보고서에는 한국어 역할명을 사용합니다. 모델은 환경 기본값을 따르고 사용자가 지정한 경우 지원되는 정확한 모델·추론 설정을 적용합니다. 지원 불가 시 대체 실행 여부를 명시하며 아스트라를 쓰지 않고 썼다고 기록하지 않습니다.

핵심 사실/계산 결함은 담당자에게 돌려 수정하고 해당 결함만 재검토합니다. 접근 불가 원문은 대체 경로를 시도한 후 제한으로 남깁니다. 검토자는 작성자의 PASS를 증거로 대신하지 않습니다. 미해결 핵심 근거가 있으면 verified 출력이나 확정 판단을 만들지 않습니다. 자동 반복은 새로운 증거·수정이 있는 동안만 수행하며 같은 막힘에서 무한 루프하지 않습니다.

총괄은 `(run_id, skill, phase, scope, input_version)` 작업키로 완료 결과를 재사용합니다. 같은 입력으로 뉴스·팩트체크를 중복 실행하지 않습니다. 수정·새 자료로 입력이 바뀌면 해당 작업만 다시 수행합니다. watchlist의 baseline 단계는 이전 판단·조건 추출만, compose는 새 자료를 받은 뒤 차이 분석만 합니다. portfolio의 prepare는 입력 점검·계산만, compose는 조사 결과와 목표를 받아 상담 대안을 작성합니다. 준비 단계에서 최종 판단을 내리지 않습니다. 조건부 단계가 생략되면 이유를 전달하고 다음 단계는 그 공백을 사실처럼 채우지 않습니다.
