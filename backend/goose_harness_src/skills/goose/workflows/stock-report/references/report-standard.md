# 승인된 보고서 기준

## 종목 심층 보고서의 구성
표지에 회사명·시장/티커·기준일·핵심 판단·확신·4개 안팎의 유효 KPI를 제시합니다. 실제 중요한 지표를 고르고 금융업 등에는 업종에 맞게 변경합니다. 본문은 다음 9장과 마지막 오피니언으로 구성합니다.
1. 사업과 수익 구조
2. 실적의 변화
3. 이익의 구성과 반복 가능성
4. 재무 여력·현금흐름
5. 산업·경쟁사·성장 가설과 반증
6. 공시·뉴스·최근 사건
7. 팩트체크 결과
8. 시나리오·판단 변경 조건
9. 조사 경로·근거 수준·한계
10. MoAI 오피니언

순이익이 매출보다 크다는 등 SK하이닉스 사례의 특수 제목·숫자·등급을 다른 회사의 기본값으로 복사하지 않습니다. 실적/마진/현금흐름 등 의미 있는 실제 자료가 있을 때만 차트를 만듭니다. 봉차트·가격 기술 분석은 범위에서 제외합니다. 비교·사건·팩트체크·상담의 단독 결과는 필요한 길이의 분석 메모로 작성하며, 단순 후속 질문에 전체 보고서를 반복 생성하지 않습니다. 최초의 “삼성전자 분석해줘” 같은 종목 분석은 짧게 요청해도 전체 보고서가 기본입니다.

## 문체·오피니언
독자인 투자자에게 전문적인 존대 평서체로 전달합니다. 결론 요약을 먼저, 상세 칼럼을 뒤에 둡니다. 상세 종목 보고서의 MoAI 오피니언은 12개 연결 산문 문단, 문단마다 최소5문장입니다. 각 문단은 하나의 논지·근거·반대 가능성·투자자 의미를 이어 설명합니다. 중복 문장으로 분량을 채우지 않습니다. 실제 자료가 모자라면 조사 또는 확인 제한을 처리하고 지어내지 않습니다. 문단별 핵심 사실에는 직접 출처를 붙입니다. 판단 카드 문구는 `🗿 MoAI의 판단`입니다. 관찰 우선순위 3상태와 근거 부족 유보를 구분합니다.

## 디자인
승인된 assets의 투명 글자 로고만 사용합니다. 상단 별도 심볼을 복원하지 않습니다. 무채색 전자잉크 배경과 작은 버건디 강조를 유지합니다. 제목은 고운바탕 CDN, 일반 본문·표·숫자·오피니언은 Pretendard CDN입니다. 제목 종목명은 700 굵기와 0.6px 획 보강을 사용합니다. 전체 본문 행간 1.6, 일반 본문17px, 오피니언19px(좁은화면18px), 모든 오피니언 문단 크기는 동일합니다. 중요 숫자·판단은 크기·굵기·여백으로 강조하며 섹션은 선형 아이콘을 사용합니다. 과도한 이모지·명조 본문·가짜 점수·형식적 위험 나열을 피합니다.

## 제작·검증
구조화 입력은 report-input.md를 읽습니다. scripts/render_report.py가 제공되면 Python3 표준 라이브러리로 실행합니다. 외부 프레임워크나 개발자의 절대 경로를 요구하지 않습니다. Python 실행이 없는 환경에서는 동일한 입력·CSS·로고로 초안 HTML을 작성할 수 있지만, 최종 감사가 실행되지 않았다면 최종본으로 표시하지 않고 실제 가능한 검증 범위를 보고합니다. 파일 생성 자체가 안 되면 Markdown 결과와 제한을 제시하며 HTML 완료를 주장하지 않습니다.

보고서·원장 ID, 단위/기간/연결 범위, 결론카드와 본문 의미, 반대근거 누락, 문단수·문장수, URL을 확인합니다. 사용 가능한 브라우저에서 실제 폰트·넘침·표/차트 가독성을 봅니다. 스크립트 통과와 렌더링·실제 설치·클라우드 실행 검증은 구별합니다. PDF는 실제 생성·확인한 경우에만 완료로 표시합니다.

## 공통 페이지 템플릿
모든 기능의 HTML 기본값은 같은 assets/report.css와 assets/modu-stock-wordmark.png입니다. document_type으로 deep_report, comparison, earnings, event, portfolio, fact_check, briefing을 고릅니다. deep_report만 9장+12문단 오피니언 기준을 적용하며 다른 유형은 필요한 섹션·표·재무 차트와 선택적 결론을 구성합니다. 비기업 페이지는 document의 제목/부제/문맥을 쓰고 가짜 기업명을 만들지 않습니다. 폰트 파일은 포함하지 않고 고운바탕·Pretendard를 CDN으로 가져옵니다. 회사 글자 로고는 플러그인 자산으로 포함하고 HTML에 내장합니다.

## 설치 후 결과 비교에서 도출한 품질 게이트

1. 12문단×5문장은 최소 형식입니다. 승인된 상세 칼럼의 밀도는 보통 문단당 7~9문장·450~700자 수준이었으며, 문장을 잘게 나누거나 같은 경고를 반복해 채우지 않습니다. 각 문단에 논지, 구체적 근거, 작동 원리, 가장 강한 반론, 투자자의 다음 확인 조건을 연결합니다. 더 짧게 끝내는 것이 타당하면 편집 검토에 이유를 기록합니다.
2. 관심종목 편입은 조사 우선순위입니다. 적정가격을 계산하지 못했다는 이유만으로 자동 관망하지 않습니다. 성장의 관찰 가치·반증·정보 공백으로 조사 우선순위를 결정하고 가격 매력 및 개인 비중 판단은 별도로 둡니다. 이전 샘플과 판단이 달라도 오류가 아니며, 같은 판단을 재현하려고 근거를 맞추지 않습니다. `opinion.decision_scope`는 `research_priority`로 기록합니다.
3. 각 담당자의 중요한 긍정·반대 논거를 본문과 오피니언의 문단 ID에 연결한 coverage 표를 `editorial-review.md`에 남깁니다. 제외하면 이유를 쓰고, 자료가 존재하는데 미확인으로 끝내지 않습니다. 자사주는 결의·개별 체결·취득 완료·소각 완료를 분리해 KIND/DART의 후속 기록을 확인합니다. 과거 보고서는 탐색의 출발점이며 이번 직접 열람으로 승격하지 않습니다.
4. 분기 추이·이익률·이익-현금 연결 등 핵심 질문에 맞는 재무 도해를 선택합니다. 검증한 기간이 충분한데 두 시점만 남겨 흐름을 지우지 않습니다. 자료가 부족하면 이유를 밝히며 개수를 채우기 위해 차트를 만들지 않습니다.
5. 단순 구조 PASS는 편집 품질 PASS가 아닙니다. `editorial_review`에 `argument_depth`, `decision_scope`, `material_coverage`, `visual_review` 각각의 `{status:reviewed|pending|limited, evidence:실제 검토 기록}`를 남깁니다. 실제 브라우저 확인이 없으면 visual_review를 reviewed로 쓰지 않습니다. 렌더러의 editorial_quality 경고는 별도 감수 대상으로 넘깁니다. 미완료 조사·감수는 사유만 붙여 최종 제출하지 않으며, 현재 입력과 화면에 대한 최종 감사 계약을 통과해야 합니다. 이 선언 자체는 독립 감사 증명이 아닙니다.
6. 중요한 숫자와 판단은 문단의 `highlights`에 원문 그대로 지정합니다. 전체 문장에 태그를 넣지 않습니다. 생성기는 안전하게 강조를 출력하며, 단일 HTML의 JSON 다운로드도 자체 내장해 폴더가 분리되어도 사용할 수 있게 합니다.
