# 이전 판단과 새 근거의 차이

[조사 계약](../stock-report/references/research-contract.md)과 [실행 지도](../stock-report/references/workflow-map.json)를 읽습니다. 이전 보고서/기준일/판단/변경조건을 먼저 확보합니다. 접근 가능한 이전 기록이 없으면 사용자에게 요청하거나 새 기준선을 만들며 기억으로 이전의견을 복원하지 않습니다.

leaf에서는 전달받은 phase만 수행하며 다른 스킬을 호출하지 않습니다.
- baseline: 기존 판단·핵심 주장·변경 조건·기준일을 추출하고 새 자료 조사 범위를 반환합니다. 이전 자료가 없으면 새 기준선 모드라고 표시합니다. 이 단계에서 변경 결론을 만들지 않습니다.
- compose: 총괄이 전달한 새 사건·실적·경쟁 결과로 유지·강화·약화·반증·미확인을 판정하고 이전/현재/변경근거 표를 반환합니다. 원 정정공시가 이전 근거를 바꾸면 수정 이유를 기록합니다.

standalone이면 실행 지도의 baseline → 필요한 자료 조사 → compose → fact-check를 한 번씩 실행합니다. 팩트체크 후 필요한 부분을 고치고 현재 관심목록 판단과 변경 조건을 제시합니다. 현재 판단을 자동으로 과거와 같게 두지 않습니다. 전체 HTML 요청이면 stock-report render로 개정본을 만들며 과거 버전은 보존합니다. 기본은 요청 시 1회 점검입니다. 예약/알림은 사용자가 따로 요청하고 실제 일정 도구로 설정된 경우에만 약속합니다.
